# Amazon Listing Growth Pipeline

Use the conversation template in [references/conversation-template.md](references/conversation-template.md). Do not ask the user to create JSON or run commands. Treat uploaded CSV and XLSM files as attachments; write normalized JSON only inside the run directory for audit and recovery.

## Workflow

1. Parse the user message and attachments with `normalize_conversation()`. Ask only when a required item is absent or contradictory: marketplace, primary ASIN, at least one variant, brand/product type, price/cost, one keyword CSV, or one XLSM report.
2. Collect product and competitor facts. Prefer user attachments and supplied facts; then use public pages. Build a localized, evidence-backed internal `listing_seed` without asking the user for Listing copy.
3. Call `amazon-keyword-research`, `amazon-listing-optimization`, `kjxj-amazon-title-optimizer`, `amazon-product-compliance`, `amazon-review-analyzer`, `amazon-search-optimization`, and `amazon-ppc-campaign` in sequence. Capture and freeze each complete Markdown reply exactly as returned before calling the next derivation. `amazon-listing-optimization` and `kjxj-amazon-title-optimizer` are different sources: never substitute either reply for the other.
4. Call `run_conversation(..., raw_skill_outputs=...)` with the normalized task, generated seed, and captured replies. Required keys are `listing_optimization`, `title_optimizer`, `ppc_campaign`, `search_optimization`, `review_analyzer`, and `product_compliance`. Do not continue to review if any required reply is absent, its frozen attachment checksum changes, or the Listing reply does not contain a Title, five bullets, description, and backend search terms.
5. Before any XLSM write, generate four review attachments from original Skill replies: `<base>-listing-optimization.md`, `<base>-title-optimizer.md`, `<base>-ppc-campaign.md`, and `<base>-rufus-qa.md`, where `<base>` is `<产品类型中文名称>-<产品类型>-<主ASIN>-<YYYYMMDD>`. The first three files contain the complete, byte-for-byte original replies from their respective third-party Skills; never summarize, rewrite, omit, merge, or replace them with Codex-generated content. The Rufus file concatenates the complete, byte-for-byte original search, review, and compliance replies under their respective Skill headings. Add Chinese review translations only directly below English Q/A pairs, without changing the original Q/A or other source text. The Listing attachment must preserve the third-party Listing Title; a 2026 Title must never be written into it. After every file-write operation, stop and verify the exact expected path exists, is a regular non-empty UTF-8-readable file, and can be read back. Compute and record a SHA-256 checksum for each frozen attachment; re-read it immediately before building the audit package and require the checksum to match. Build `*-sync-review.md` by reading and concatenating the actual four frozen attachment files, never by regenerating their content in memory. Then build `<base>-chinese-summary-review.md` from the actual review files and preflight result. After creating `*-sync-review.md`, the Chinese summary, and `overview.md`, verify all seven expected files exist and that every link target is an existing absolute path. Do not show a file link, state that an attachment was generated, or ask `确认回填` unless this verification passes. On any write or patch error, report the error, do not fabricate fallback links, and retry only with a syntactically valid edit after re-reading the target directory. Deliver the four attachments, the Chinese summary, and named `*-sync-review.md` as clickable, in-conversation Markdown preview links. If the current client cannot open any one of those links as a conversation preview, immediately render that attachment's complete verified Markdown body in the same response; apply the same fallback to the audit package. `overview.md` is navigation only and never replaces an attachment or the audit package. State that no XLSM has been written. Ask only: `确认回填`.
6. After that exact approval, call `command_approve()`, which must invoke `kjxj-sync-product-listing` only. Validate the standard output name, source checksum, header rows, retained target/parent rows, deleted unrelated rows, written values, green fill, and OOXML integrity. Show [delivery.md] and provide the resulting XLSM with a Codex workbook output citation. Do not modify the source workbook.

## Evidence and Safety Rules

- Keep unverified facts as `Pending confirmation`; never turn them into claims.
- Keep child variant facts separate unless inheritance is verified.
- Mark PPC defaults as assumptions: 15% referral fee, zero FBA/shipping fee, and daily budget 8. Never call the result a true break-even calculation.
- Treat missing review evidence as an evidence gap, not customer sentiment.
- Block only when a conflict or missing required source would make the output inaccurate. Continue through non-critical evidence gaps.

## Artifact Delivery Gate

- Treat a failed `apply_patch`, file-write command, checksum, or read-back as a failed artifact delivery. A failed patch is atomic unless independently proven otherwise; inspect the output directory before referring to any expected file.
- Use the editing tool's required unified-patch syntax exactly. In an `Add File` hunk, prefix every content line, including blank lines and lines inside fenced code blocks, with `+`. When an edit fails, do not assume a partial file exists.
- Verify with a read-only directory listing plus a non-empty UTF-8 read-back for the four frozen attachments, `*-sync-review.md`, `*-chinese-summary-review.md`, and `overview.md`. Validate every preview link against its exact existing absolute path.
- Keep an internal manifest of expected paths and SHA-256 values. A final user-facing preview link may be emitted only when its exact path is present in the manifest, passes the last read-back check, and is accompanied by a complete-content fallback plan.
- A clickable local Markdown link is a preferred preview mechanism, not proof of successful delivery. If the client does not expose a conversation preview for a link, immediately render the entire verified file content in the response. Do not provide only paths, filenames, link lists, or an overview as a substitute.

- The named `*-sync-review.md` audit package is the only approval gate. It must link to and then concatenate the complete contents read from the four frozen original-output attachment files without summarizing, parsing, rewording, omitting, or substituting content. The fixed order is Listing Optimization, Title Optimizer, PPC Campaign, then Rufus Q/A. Validate each embedded body against its frozen source checksum before delivery. Add only a uniform separator and source filename before each body. Immediately after the unchanged PPC body, add a `PPC 关键词复制区` derived only from that PPC Markdown: group positive keywords and negative keywords by campaign in separate code blocks, with one keyword per line and no bids, match types, explanations, or product-targeting ASINs. Block review generation when no PPC keywords or negative keywords can be parsed. Append the XLSM plan and `确认回填` instruction after the fourth body. The review must state that XLSM Title and Item Highlights use the separately selected 2026 title option; no 2026 value may be labelled as an original Listing field.
- Build `<base>-chinese-summary-review.md` as an additional audit attachment, not an approval gate and not a substitute for any frozen output. Its headings, field labels, explanatory text, risk notes, and audit translation must be Chinese. Preserve marketplace copy, keywords, campaign names, currencies, ASINs, and all other source-language values verbatim; do not use Chinese translation as Listing or XLSM data. Extract the normal Listing Title, 2026 short Title, Item Highlights, five bullets, description, backend search terms, every available PPC campaign, the `PPC 关键词复制区`, and Rufus Q/A from the actual review files. Preserve every source Q/A and put its Chinese audit translation directly below it. If fewer than eight Q/A pairs exist, add only evidence-backed Q/A from verified specifications, variants, installation, care, or stated evidence limits until there are eight; label unknown answers `待确认`. Preserve all source Q/A when more than eight exist.
- Include `## XLSM 回填说明` in the Chinese summary before the evidence-boundary section. Generate it from the read-only preflight result and the normalized task without binding it to a marketplace, language, ASIN, product type, worksheet, or display-field name. State the output-copy naming rule, marketplace/report/worksheet/ASIN/parent evidence, selected 2026 title option, confirmed field mappings and sources, row handling, `#C6EFCE` change marking, preserved fields, and post-write OOXML verification. When preflight cannot establish a row, field mapping, or station evidence, state `待预检确认` or `无法执行`; never invent column names, row numbers, or write values. State that no XLSM has been written until explicit approval.
- Include the Chinese summary in `overview.md` and the SHA-256 manifest. Do not emit its preview link unless all seven audit files pass the final non-empty UTF-8 read-back and checksum verification.
- Do not render internal JSON keys, nested structures, or audit metadata such as `source`, `captured_at`, and `reports` in `*-sync-review.md`. Keep that data only in the JSON audit artifacts and manifest.
- Preserve every English question and answer in the review package. Add a Codex-generated Chinese review translation directly below each pair, label it `仅供审核`, and never write the translation back into Listing copy, original Skill replies, or source JSON. If a non-conversation integration does not supply a translation, show `待确认`.
- `delivery.md` links Listing, 2026 title, PPC, Rufus, compliance, search optimization, and the final XLSM. Internal sync JSON retains the third-party Listing fields in `listing` and the separately captured 2026 output in `title_options_2026`; the synchronizer uses the selected 2026 option only for Title and Item Highlights.
- The final workbook must use `YYYY-MM-DD_Amazon<站点>_分类商品报告_Listing同步完成_<ASIN数量>ASIN_vN.<扩展名>`. From row 7 onward, retain only updated child ASIN rows and direct parent rows; delete all other data rows and mark only changed Listing cells with `#C6EFCE`.
- Keep the CLI as an internal/developer compatibility interface only; never direct a seller to use it.
